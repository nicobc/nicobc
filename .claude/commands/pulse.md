---
description: Portfolio pulse check — what's built, how it reads to hiring teams, seniority signal, good/bad, what's next
---

Read the current project state (git status, routes, pages, services, data pipeline modules) and answer the following as a senior engineering hiring manager who has reviewed hundreds of DE portfolios:

1. **What have we built?** Summarize the current state of the portfolio concisely — what's live/working, what's in progress, what's wired together end-to-end.

2. **How does this compare to a typical DE portfolio?** Most DE portfolios are a GitHub repo with a few notebooks and a README. Be specific about what makes this different (or the same).

3. **Career impact — how likely is this to matter?** Give an honest assessment. Consider: would a hiring manager who saw this actually remember it? Does it move the needle for inbound interest, interview performance, or offer negotiation?

4. **Seniority signal.** Based on the choices made (architecture, tooling, code structure, scope), what level of engineer does this signal — IC3, IC4, IC5, staff? Explain which specific signals point up and which point down.

5. **The good and the bad.** What's genuinely impressive? What's weak, missing, or could backfire?

6. **What's planned but not yet built?** Based on the codebase, comments, memory, and anything discussed — what's already been decided or scoped that hasn't landed yet? This is the backlog as it exists, not recommendations.

7. **What should be next?** Given the current state and career goals of a staff DE, what's the single highest-leverage next move — not a laundry list, just the one thing that would move the needle most right now, regardless of what's already planned.

Be direct and specific. Avoid generic praise. If something is unfinished or weak, say so plainly.
